============================================================
0. 文档定位
============================================================

本文依据用户提供的《DSH 零基础全流程教学·图文版》（2026-11-03），
结合现有 TANK-AI-Companion 项目，提出产品创新和架构升级方案。

借鉴产品理念和交互方式，不代表已审计或验证 DSH、SurfCore、
SnowLuma 等项目源码、第三方仓库、插件、安装脚本或下载地址。

实施原则：先只读检查；最小权限；插件隔离；高风险操作审批；
不把第三方插件或 Agent 默认视为可信。

============================================================
1. 产品愿景
============================================================

产品名称：TANK-AI-Companion
升级定位：大肥鱼 AI 个人操作系统
核心角色：大肥鱼（原版与 Q 版为同一个角色）
部署基础：Unraid 7.3.2
AI 主控：Hermes Agent
模型网关：Magpie
入口：Telegram Bot + Telegram Mini App + Web Office
运维工具：UnraidClaw、MoviePilot V3 等受控连接器

目标：
1. 有稳定人格、长期记忆和主动能力的 AI 角色。
2. 通过自然语言创建工作流、插件和个人工作台。
3. 统一管理 Plugin、Skill、MCP、API 和自动化。
4. 手机、网页和未来桌面端体验一致。
5. 管理专业 Agent，处理陪伴、研究、媒体和 NAS 运维。
6. AI 能做事，但不能绕过权限和审批。

2. DSH 教程功能映射
============================================================

DSH 标准模式 -> 大肥鱼日常模式：聊天、问答、普通任务。
DSH PTC 模式 -> 大肥鱼批处理模式：批量整理、巡检、汇总。
DSH 极简模式 -> 大肥鱼轻量模式：快速响应、少工具、低成本。
DSH 创造模式 -> 大肥鱼创造工坊：自然语言生成插件、页面和工作流。
DSH 插件市场 -> Tank Plugin Hub：统一管理插件、Skills、MCP。
DSH 动态壁纸 -> 大肥鱼主题中心：Q版形象、办公室主题、动态背景。
DSH 开机动画 -> Web Office 启动动画和角色欢迎，不改 NAS 启动流程。
DSH Go -> Telegram + Mini App + PWA 手机端。
DSH Remote -> 远程工作台：查看任务、审批、控制授权工作流。
SurfCore 桌宠 -> 大肥鱼数字生命：角色状态、主动陪伴、桌宠。
本地/云端语音 -> 语音中心：语音输入、TTS、语音对话。
QQ / B站 -> 可选社交连接器，独立授权、账号隔离。
人格卡 -> 人格工坊：导入、编辑、版本管理。
/compact -> 上下文管家：用量、摘要、压缩和记忆管理。
环境安装 -> 环境检查助手：检查依赖、生成计划、确认后安装。
文件整理/磁盘清理 -> 智能文件管家：扫描、预览、风险评级、审批后执行。

关键判断：
DSH 是桌面本地 Harness，强调本机文件、终端和桌面权限；
TANK-AI-Companion 是服务器侧长期运行的个人 AI 平台。
不能照搬桌面端“完全权限”模式到 Unraid 服务器。

3. 四种工作模式
============================================================

A. 标准模式
日常聊天、问答、轻量任务；按需调用授权工具。

B. 批处理模式
批量文件整理、媒体检查、服务巡检、数据汇总。
先生成计划、影响范围和预览；支持 dry-run；写操作逐项审批。

C. 轻量模式
快速问答、状态查询、简单提醒。
优先低成本模型，限制工具调用，避免不必要的长上下文。

D. 创造模式
自然语言创建插件、页面、工作流、Agent 角色和主题。
流程：需求澄清 -> 设计草案 -> 代码生成 -> 静态检查 ->
沙盒测试 -> 权限审查 -> 用户确认 -> 发布 -> 监控与回滚。
生成器不能自行批准自己创建的插件，也不能直接取得宿主机权限。

============================================================
4. 大肥鱼数字生命与人格工坊
============================================================

角色状态：
待机、聊天、思考、执行任务、等待审批、工作完成、异常、休息。

能力：
- 稳定人格、称呼和表达风格。
- 经授权的主动问候和定时关怀。
- 日记、纪念日和成长记录。
- Web Office、Mini App、未来桌宠共享角色状态。
- 原版、Q版属于同一个角色身份。

人格工坊：
- 人格卡导入和模板预览。
- 核心人格、语气、场景规则分层。
- 人格版本管理、差异比较和回滚。
- 人格变更需 Owner 确认。
- 人格不能改变系统安全策略和工具权限。

边界：
不伪称真实意识；不利用主动消息制造依赖；
主动联系可关闭；成长记录可查看、纠正和删除。

============================================================
5. Tank Plugin Hub 插件生态
============================================================

统一登记：
1. UI 插件：页面、组件、主题。
2. Tool 插件：单一工具能力。
3. Skill：可复用操作说明和步骤。
4. MCP Connector：外部工具或数据连接。
5. Workflow：多步骤自动化。
6. Agent Pack：角色提示词、工具范围和任务模板。
7. Theme：Web Office 和 Mini App 视觉主题。

管理功能：
目录、搜索、详情、作者、版本、安装、启停、升级、卸载、
依赖检查、兼容性、权限清单、健康检查、日志、版本锁定、
备份、回滚和来源标识。

建议首批插件：
Unraid 管家、Docker 管家、MoviePilot 管家、Emby/Plex 管家、
网络管家、文件整理助手、资料研究员、语音中心、
日记与记忆工具、会话统计、任务看板。

权限等级：
P0 展示：静态或已提供数据。
P1 用户数据读取：仅当前用户明确授权的数据。
P2 服务只读：NAS、Docker、媒体服务状态。
P3 受控写操作：必须 Owner 二次审批。
P4 高危系统权限：默认禁用，原则上不向普通插件开放。

安全原则：
安装插件不等于授予权限；插件不得自行提升权限；
不得默认获得 Docker Socket、宿主机 root 或 privileged；
不可信插件必须隔离运行。

============================================================
6. 创造工坊：自然语言造插件
============================================================

用户可提出“做一个 NAS 状态卡片”“做一个媒体整理工作台”
“做一个 Token 统计页面”“做一个批量巡检工作流”等需求。

标准流程：
1. 需求澄清。
2. 生成设计草案。
3. 在隔离工作区生成代码。
4. 静态检查危险 API 和密钥。
5. 沙盒运行。
6. 评估读写权限和外部连接。
7. 向用户展示差异、风险和权限。
8. 用户确认安装。
9. 登记版本、作者和校验信息。
10. 监控运行并支持停用、回滚。

禁止自动获得宿主机权限、硬编码密钥或未经确认执行删除、
覆盖、重启、更新等操作。

============================================================
7. 手机端与远程工作台
============================================================

入口：
- Telegram Bot：聊天、通知、审批。
- Telegram Mini App：手机管理控制台。
- Web Office：完整工作台。
- PWA：添加到手机主屏幕。
- 未来桌面端：桌宠、通知和快捷入口。

远程工作台：
查看 Agent 状态、任务步骤、日志和产物；
暂停或取消允许取消的任务；
查看待审批事项并审批具体操作；
远程提交新任务。

安全：
HTTPS；服务端验证 Telegram initData；
短期会话和设备授权；敏感操作二次验证；
审批绑定用户、动作、参数和有效期；
不通过二维码或聊天记录暴露长期密钥；
不直接向公网开放 NAS 管理端口。

============================================================
8. 语音中心、桌宠与主题中心
============================================================

语音中心：
语音输入转文字、本地/云端 TTS、音色选择试听、
服务健康检查、语音开关和隐私设置。

APP ID、Access Token、音色 ID 等由后端安全保存；
前端只显示脱敏信息；日志不记录密钥；
云端语音需说明数据会发送到第三方。

桌宠与主题：
初期先实现 Web Office 内 Q 版大肥鱼和状态动画；
后续再开发 Windows/macOS 桌面端。
动态壁纸、启动动画属于外观主题，不改变 NAS 启动流程。
桌宠不能绕过后端权限控制。

============================================================
9. 社交平台连接器
============================================================

可评估 QQ、Bilibili、Telegram 等连接器。
每个平台独立适配器、独立授权、独立凭证和账号隔离。
使用专用测试账号；最小范围授权；用户可随时断开。
先核验官方 API、服务条款和第三方项目风险。
不将未经验证的协议网关作为核心依赖。
不默认读取全部聊天、联系人或群组。

============================================================
10. Agent 团队
============================================================

大肥鱼总经理：
Hermes 主控，理解目标、拆解任务、调度和汇总。

专业角色：
- NAS 管家：Unraid、Docker、存储只读检查。
- 媒体管家：MoviePilot、Emby、Plex。
- 网络管家：GL-BE6500、DNS、代理和网络状态。
- 研究员：资料检索、技术比较和报告。
- 记忆管理员：记忆、日记和经验。
- 创意设计师：页面、主题、图片和文档。
- 自动化工程师：工作流和插件草案。

初期可用 Hermes 的角色配置、Skills 和工具权限模拟团队，
不必一开始就为每个 Agent 部署独立容器。
Hermes 统一调度；Magpie 提供模型路由。
每个 Agent 只获得完成任务所需工具，不能自行扩大权限。

============================================================
11. AI Office 工作台
============================================================

延续已确认的视觉基准：
深色科技风、中央等距 3D Q 版机器人办公室、左侧导航、
右侧大肥鱼总监与员工动态、顶部团队 KPI、
底部工作统计、服务监控和待办任务。

页面：
总览、AI 团队、任务中心、插件中心、创造工坊、记忆中心、
日记、语音中心、主题中心、NAS 运维、媒体中心、
用户与好友、系统设置。

组件：
Agent 状态卡、任务看板、实时事件流、待审批列表、
Token/成本统计、插件健康状态、NAS 服务状态、角色状态。

数据必须来自真实后端；演示数据明确标记为模拟数据。

============================================================
12. 上下文与记忆引擎
============================================================

Companion 记忆：
用户偏好、陪伴经历、日记、好友关系、授权个人记忆。

Hermes 记忆：
运维知识、项目配置、Skills/MCP 经验、任务经验、LESSONS.md。

通过明确 API 交换必要信息；不默认共享原始聊天记录；
不同用户之间完全隔离。

上下文管家：
当前会话摘要、长期记忆检索、上下文用量展示、
阈值提醒、自动摘要、压缩记录和重要决策保留。
Token 数据需标注模型实测值或估算值。
不将未确认推断写成用户事实。

============================================================
13. Unraid 智能运维安全
============================================================

第一阶段只读：
Docker 容器、CPU、内存、磁盘容量和可用温度、
Unraid、MoviePilot、Emby、Plex、网络服务状态。

第二阶段受控写操作：
重启指定容器、更新指定容器、修改白名单配置、
执行审核通过的维护工作流。

安全底线：
不挂载 Docker Socket 给 Companion；
不使用 privileged；不公开 Hermes 管理 API；
好友不能执行 NAS 写操作；插件不能自行执行宿主机命令；
不自动删除用户或系统数据。

审批必须绑定用户 ID、任务 ID、动作、目标、参数摘要和有效期。
执行前再次校验权限和目标状态。
记录执行人、审批人、结果、时间和回滚信息。

17. 验收标准
============================================================

- Telegram 和网页身份一致，用户数据严格隔离。
- 大肥鱼人格稳定，原版与 Q 版为同一角色。
- 手机和网页看到一致任务状态。
- Agent 工作过程可查看。
- 记忆和日记可查看、纠正和管理。
- 插件有来源、版本和权限清单。
- 未授权插件不能访问敏感资源。
- 插件可停用和回滚。
- NAS 写操作必须审批并留下审计记录。
- 不泄漏密钥，不授予不必要系统权限。
- 有备份、恢复、升级和回滚说明。

19. 设计结论
============================================================

TANK-AI-Companion 不应成为 DSH 的简单复刻版。
它应当成为以大肥鱼为统一人格的个人 AI 操作系统：

有心：人格、陪伴、记忆、日记。
有脑：Hermes 主控与专业 Agent。
有手：插件、Skills、MCP 和工作流。
有眼：任务状态、上下文统计、服务监控。
有声音：本地/云端语音适配。
有身体：Telegram、Mini App、Web Office 和未来桌面端。
有边界：用户隔离、最小权限、审批和审计。

最终目标：
让大肥鱼既能陪伴用户，也能管理任务、组织 Agent、扩展插件、
连接服务并协助运维；同时始终由用户掌握数据、权限和最终决定权。
