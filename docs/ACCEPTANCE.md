## 第 17 节：验收标准
| 标准 | 状态 | 验证方式 |
|---|---|---|
| Telegram 和网页身份一致，用户数据隔离 | ✅ | 同一套服务与 `resolveUser`；测试覆盖隔离、路径穿越、好友越权 |
| 原版与 Q 版为同一角色 | ✅ | 两种形象共用名称/配色/状态；`/api/prefs` 的 `form` 可切换 |
| 手机和网页看到一致任务状态 | ✅🔶 | 单一服务端状态源，页面 5–8 秒轮询；手机/网页并排需你肉眼确认 |
| Agent 工作过程可查看 | ✅ | `GET /api/tasks/:id`，Office / Mini App 点击任务看步骤 |
| 记忆和日记可查看、纠正、管理 | ✅ | `/fix`、自然语言“更正 <编号> …”、Office/Mini App 编辑 |
| 插件有来源、版本和权限清单 | ✅ | 清单校验 + 插件中心展示 |
| 未授权插件不能访问敏感资源 | ✅ | 运行时逐层检查，测试覆盖 |
| 插件可停用和回滚 | ✅ | 停用；生成插件回滚版本；内置插件撤销上次变更 |
| NAS 写操作必须审批并留审计 | ✅🔶 | 一次性审批 + 白名单 + 审计，测试覆盖；真实写入需实测 |
| 不泄漏密钥、不授予不必要权限 | ✅ | 测试扫描响应/审计/配置输出无密钥；P3 仅 Owner、写类权限仅内置插件可授予 |
| 备份、恢复、升级、回滚说明 | ✅📄 | `docs/OPERATIONS.md` + `scripts/backup.sh`、`restore.sh`（有往返测试） |
